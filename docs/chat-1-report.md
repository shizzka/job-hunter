## Правила решений

Автор определяется прежним классификатором: CSS исходящего, известные маркеры
ИИ-помощника, отдельно подозрительный скрининг. Новые основания классификации
сохраняются для анализа; AI-whitelist и булевы правила автора не расширены.

Действие определяется отдельно в `chat_triage.py:67`:

1. Рассматриваются входящие после последнего видимого исходящего. Если после
   нашего ответа входящих нет, решение `ours_last`; старый вопрос не поднимается.
2. Прежние дедупликация ответов/preview и лимит ответов сохраняются.
3. Google Forms обрабатываются прежним обработчиком с прежним приоритетом,
   включая ссылки в более ранних входящих. Уже учтённая форма не превращается
   в новую карточку HR.
4. Подтверждённый ИИ-помощник идёт в прежний путь `ai_hh_autoreply`.
5. Остальные входящие с Telegram-ссылками или явными внешними ссылками на
   тест/анкету/опрос получают `external_invite`.
6. Только явно известные системные уведомления и точные приветствия/подтверждения
   получают `system_notice`/`no_question`. `?`, вопросительные слова, просьбы
   уточнить/прислать/рассказать, интерактивные элементы означают `hr_question`.
   Неоднозначное непустое входящее также получает `hr_question`.
   Пустое нечитаемое сообщение или отсутствие ID — `unknown`.

| Синтетический пример | Решение |
| --- | --- |
| ИИ-помощник: «Работодатель хотел бы узнать: опыт SQL?» | Прежний автоответ с прежними защитами |
| HR: «Когда сможете приступить?» | Карточка с «Ответить с ИИ»; генерации/отправки при сканировании нет |
| HR: «Пришлите портфолио» | Та же карточка |
| HR: «Предлагаем обсудить детали завтра» | Неоднозначное входящее → карточка человеку |
| HR: «Пройдите тест по Python: https://example.org/test/42» | Карточка «Приглашение пройти: тест по Python» со ссылкой |
| HR: «Наш бот: t.me/synthetic_bot» | Карточка приглашения со ссылкой; кнопки ИИ нет |
| `telegram.me/synthetic_bot`, `tg://resolve?domain=synthetic_bot` | Та же ручная обработка приглашения |
| «Заполните https://forms.gle/synthetic» | Существующий путь Google Forms |
| HR-вопрос → наш ответ | `ours_last`, новой карточки нет |
| «Спасибо!» / «Здравствуйте» без дополнительного текста | `no_question` |
| «Работодатель просмотрел ваше резюме» | `system_notice` |

Спорные случаи: Telegram-ссылка может вести в канал/портфолио, а не в бота;
она всё равно направляется человеку как внешний этап. Ссылка без признаков
теста/анкеты на обычный сайт сама по себе не является приглашением; непустое
неоднозначное входящее направляется в HR-карточку. Для внешнего задания в Google
Docs работает приглашение, для Google Forms сохраняется отдельный путь.
`not.me/...` и поддомен `t.me.evil.example` не распознаются как Telegram.
Если DOM ошибочно пометит сообщение исходящим, автор не переопределяется по
старому вопросу: это проверяется диагностическим снимком. История не догружается.

Карточки реализованы в `hh_chat_responder.py:666`. Обычный HR использует
существующий callback `chat_ai_any`; подозрительный скрининг сохраняет `chat_ai`.
Генерация, учёт кредитов и очередь — существующий `_start_chat_ai_reply`
(`telegram_bot.py:3495`). Черновик получает «Другой вариант» / «Отправить» с
привязкой к ревизии. Внешнее приглашение содержит только URL-кнопки, без AI-action.
Текст карточки обрезается и экранируется; полный текст остаётся локально.

## Охват и отсутствие повторных карточек

`hh/chat.py:144` сначала прокручивает список наверх и собирает верхнее окно.
Затем обходит виртуальный список перекрывающимися шагами до устойчивого низа
либо предела 60 шагов. `list_complete=true` означает только подтверждённый
низ текущего DOM-списка, а не серверное число всех чатов. Без доказанного конца:
`false`, причина `no_scroll_container` или `step_limit`.

Состояние выбора: `~/.job-hunter/profiles/<профиль>/chat_scan_state.json`.
`next_chat_id` — курсор, `observations` — отпечатки полного текста строк,
предыдущая непрочитанность и ожидающий приоритет. Это отдельное состояние
профиля, не затрагивающее claims отправки (`chat_observation.py:79`).

Непрочитанность определяется только по явным DOM-атрибутам/меткам; запасной
сигнал — изменение исходного текста превью, включая часть после 300 символов.
Приоритет сохраняется до выбора, потребляется для наблюдённой версии и не
захватывает все проходы из-за неизменной метки unread. Курсор заполняет остальные
места пачки. При постоянном приоритетном потоке сохраняется минимум одно место
для курсора; при лимите 1 приоритет и курсор чередуются. Лимит открываемых для
сканирования чатов сохраняется. Стабильные 60 чатов с лимитом 25 охватываются
за три прохода, в том числе с unread в хвосте.

Карточка резервируется существующим `repository.attempt(chat_id, "notice", message_id)`
до ожидания Telegram. Завершённая или неопределённая доставка той же пары не
повторяется, даже после появления более нового сообщения. Редактирование текста
при том же ID не создаёт новую карточку; новый ID создаёт новую. Неопределённая
доставка требует ручной проверки, автоматического повтора нет.

## Журнал

Путь: `~/.job-hunter/profiles/<профиль>/chat_journal.jsonl`.
Каталог профиля `0700`, JSONL и его lock `0600`; запись сериализована `flock`,
с `O_APPEND`, `O_NOFOLLOW`, flush и fsync (`chat_observation.py:34`).
Куки, storage, заголовки и транспортные объекты не сериализуются.

Общие поля: `schema_version`, `snapshot_id`, `run_id`, `observed_at` (UTC), `profile`, `event`.

- `chat_list_snapshot`: `list_complete`, `stop_reason`, `rows[]` с `chat_id`,
  позицией, исходным полным `raw_text` строки и нормализованным `preview` до 300
  символов, непрочитанностью и её основанием. Запись: `hh_chat_responder.py:1309`.
- `chat_thread_snapshot`: чат, вакансия/компания, всегда честное
  `history_complete=false`, сообщения в порядке DOM. Полный исходный bubble
  сохраняется в `raw_text`; текст вопроса без обрезки — в `text`. Также ID,
  `dom_index`, автор из DOM, направление, булевы признаки автора и их основания,
  ссылки, тексты кнопок, доступное время. В `controls` снимка — видимые кнопки
  страницы, включая варианты ответа возле редактора. Сериализация:
  `chat_observation.py:55`, основная точка `hh_chat_responder.py:1376`.
- `chat_decision`: `chat_id`, `message_id`, решение, причина, `snapshot_ref`.
  Запись и лог метаданных: `hh_chat_responder.py:1320`.

Пример трёх связанных событий, синтетика (общие служебные поля здесь сокращены):

вопросов/ответов. Telegram получает требуемые обрезанные карточки и существующие preview.

## Диагностические снимки

`HH_CHAT_DIAGNOSTIC_SNAPSHOTS=0` по умолчанию. При значении N резервируются
первые N `hr_question` и первые N `ours_last` с видимым входящим вопросом выше
(до 2N комплектов). Резервации сохраняются между проходами/перезапусками;
неудачный снимок также расходует резерв, чтобы не повторять диагностику бесконечно.

`chat_observation.py:128`: в `chat_diagnostics/` профиля сохраняются HTML только
сообщений, PNG текущего окна и JSON со ссылкой на снимок журнала. Каталог `0700`,
все файлы `0600`. Полная страница с bootstrap-скриптами, cookies и storage не
сохраняется. Дополнительных переходов, генерации и действий на странице нет.
Реальная разметка hh и авторство этим офлайн-запуском не подтверждались —
владелец включит флаг на dev-боте.
