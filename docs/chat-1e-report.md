# CHAT-1e: почти-дословные цитаты в подтверждаемых черновиках чата

Рабочая ветка: `integration-2026-10-16`, исходный HEAD `ee53f42`
(CHAT-1d поверх CHAT-1c `2cc6be6`). Проверка и реализация локальные;
обращений к hh, Telegram и моделям не было.

## Причина и изменение

CHAT-1c показал офлайн: источник `salary` уже содержит зарплатное правило,
но `answer_grounding.validate_answer_check()` всегда передавал порог 1.0.
Перефразированная цитата давала `nonliteral_quote`. Исторический подтип
живого отказа CHAT-1c не устанавливал.

`verify_answers()` и `validate_answer_check()` теперь принимают явный
`quote_min_similarity`, по умолчанию 1.0. Параметр передаётся существующему
`cover_grounding.validate_check()`; алгоритм писем не менялся. Сохраняются
проверки полноты, источников, вердикта, коротких цитат менее восьми слов,
отрицаний и цифр. Цифры ответа сверяются с реальным непрерывным фрагментом
источника, выбранным алгоритмом, а не с приблизительной цитатой модели.

## Граница подтверждения

| Путь | Порог |
| --- | --- |
| `process_one(dry_run=True)`: «Ответить с ИИ», ручной HR-вопрос, подозрительный скрининг, другой вариант | `CHAT_DRAFT_QUOTE_MIN_SIMILARITY`, по умолчанию 0.85 |
| `process_all`: `ai_hh_autoreply`, включая автоматический dry-run | 1.0 |
| `process_one(dry_run=False)` без сохранённого одобренного черновика | 1.0 |
| Вопросы анкет `hh/forms.py`, `google_forms/answering.py` | 1.0 |

Настройка читается только при подготовке ручного preview и явно передаётся
через `_execute_reply()` → `generate_answer()` → `verify_answers()`.
Некорректные значения, NaN, бесконечность и значения вне [0, 1] дают 1.0
через общий нормализатор писем. Автоматический скан не получает смягчение:
его dry-run показывает уведомление без обязательного подтверждения каждого
ответа. Для новой непосредственной отправки `_execute_reply()` дополнительно
принудительно использует 1.0. Глобального переключателя проверки нет.

## Отправка одобренного черновика

Повторной модельной проверки фактов в существующем пути отправки **нет**.
В `_execute_reply()` ветка `stored` читает `draft['answer']`, минуя
`generate_answer()`; единственные чат-вызовы `verify_answers()` находятся
в генераторе. Низкоуровневый `hh/chat.py:send_message()` проверяет отправку,
не факты кандидата. Дополнительный аудит при отправке не добавлялся.

Порог, использованный при подготовке, сохраняется в
`draft['quote_min_similarity']` как метаданные проверки. При отправке
используется уже проверенный текст этой ревизии, поэтому текущая настройка
не может повторно отклонить его строгим порогом. Старые черновики без нового
поля остаются читаемыми и отправляются по прежним проверкам ревизий.

Перед отправкой сохраняются проверки токена ревизии, SHA-256 текста,
ревизии кандидата/профиля и контекста вопроса. Черновик повторно читается
под claim; после ожиданий проверяется актуальность сообщения, а перед
границей отправки — черновик и актуальный снимок кандидата. Защита текста
в браузере и состояния неопределённой отправки не менялись.

Тест проходит полный `process_one` preview → send для AI, HR и подозрительного
скрининга: сначала черновик готов с порогом 0.85, затем настройка меняется
на 1.0, отправляется ровно сохранённый текст с его токеном ревизии.
За весь цикл только два вызова фиктивной модели: генерация и исходный аудит.

## Регрессии и проверки

Новые локальные сценарии покрывают:

- зарплатное правило с близкой цитатой → готовый preview, без отправки;
- выдуманную зарплату в ответе и в цитате → `number_mismatch`, даже при
  наличии этой цифры в другом, удалённом участке источника;
- тот же ответ в автоматическом AI-сценарии и прямой отправке → отказ;
- настройку 1.0 и некорректные значения → строгий отказ близкой цитате;
- дословную цитату при 1.0 → готовый preview;
- короткую цитату, изменение отрицания, недостаточную близость → отказ;
- ответы анкеты при смягчённой настройке чата → строгий отказ;
- одобренный preview → send без повторной генерации или строгого отказа.
