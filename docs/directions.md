# Направления поиска

Направление — отдельное резюме, поисковые запросы и ключевые слова. Факты о человеке общие: knowledge связывается симлинком, KB-RETRIEVE отбирает релевантные факты для вакансии или вопроса. `[DO_NOT_CLAIM]` и `[LIMIT]` обязательны независимо от направления. Допуски, группа электробезопасности и срок их действия должны быть подтверждены источниками; название вакансии их не подтверждает.

## Создать направление

1. Создать `~/.job-hunter/profiles/<direction>/profile.env` и положить направленное резюме в соседний `resume.md`. Путь резюме именованного профиля рассчитывается автоматически; `RESUME_FILE` в `profile.env` не поддерживается. На hh выбрать соответствующее резюме через `HH_PRIMARY_RESUME_ID` и `HH_PRIMARY_RESUME_TITLE`.
2. Задать `HH_SEARCH_QUERIES`, `VACANCY_FILTER_POLICY=generic`, `VACANCY_RELEVANT_KEYWORDS` и при необходимости `VACANCY_EXCLUDE_KEYWORDS`. Разделитель списков — `||`. Поиск проверяет ключевые слова без учёта регистра в названии и сниппете. При пустых relevant keywords `generic` пропускает любую профессию на оценку; военные вакансии и явно заданные исключения отсекаются всегда.
3. Создать обычный каталог `~/.job-hunter/knowledge` и наполнить его общими подтверждёнными фактами этого же кандидата либо использовать уже существующий общий каталог. Если факты пока лежат в `profiles/qa/knowledge`, сначала согласовать и перенести их в общую базу; затем связать `knowledge` каждого направления с ней. Пример для уже подготовленной общей папки:

   ```bash
   mkdir -p ~/.job-hunter/profiles/electrician
   ln -s ~/.job-hunter/knowledge ~/.job-hunter/profiles/electrician/knowledge
   ```

   Поддерживается только ссылка из `profiles/<direction>/knowledge` ровно в `<общий home>/knowledge`. Общая папка должна быть обычным каталогом: ссылки на каталоги других направлений, произвольные внешние каталоги и симлинки отдельных файлов запрещены. KB-RETRIEVE открывает общий каталог напрямую через дескриптор общего home, не следует динамически заменённой ссылке.

   Существующую папку `knowledge` сначала проверить и согласовать содержимое: не заменять её вслепую. `profile_note.md` тоже станет общим; в нём должны быть факты о человеке, без указания единственной целевой профессии или обязательного QA-позиционирования. Направление определяется текущим резюме. В общей базе допустим опыт разных профессий; ненужные для вакансии факты не становятся поводом писать о них.
4. Для дополнительных источников отдельно задать их запросы/пути и резюме либо выключить источник: исходные настройки ориентированы на QA. Вызывать агент с `--profile <direction>`; `preview` позволяет проверить результаты перед включением другого режима.

## Пример `electrician/profile.env`

```dotenv
VACANCY_FILTER_POLICY=generic
VACANCY_RELEVANT_KEYWORDS=электромонтаж||электромонт||электрик||техник-электрик||электромеханик||слаботоч
VACANCY_EXCLUDE_KEYWORDS=

HH_ENABLED=1
HH_SEARCH_QUERIES=электромонтажник||электромонтёр||электрик||техник-электрик||электромеханик||монтажник слаботочных систем||слаботочник
HH_SEARCH_REMOTE_ONLY=0
HH_SEARCH_EXPERIENCE=
HH_APPLICATION_MODE=preview
HH_PRIMARY_RESUME_ID=<ID резюме электрика>
HH_PRIMARY_RESUME_TITLE=Электрик / Электромонтажник

SUPERJOB_ENABLED=0
HABR_ENABLED=0
GEEKJOB_ENABLED=0
```

`resume.md` содержит реальный опыт электрика, задачи, оборудование, образование и подтверждённые допуски. Этот пример не устанавливает кандидату стаж или группу. Быстрый поиск демона при `generic` использует те же `HH_SEARCH_QUERIES`; общий QA-список `HH_FRESH_SEARCH_QUERIES` применяется только при `qa`. География поиска остаётся общей настройкой (`config.py:82`), политика профессии её не меняет.

У QA-профиля оставляют `VACANCY_FILTER_POLICY=qa` (значение по умолчанию). Политика и ключевые слова именованных профилей не наследуются от ранее активного направления (`profile.py:556`, `profile.py:821`).

Они сами по себе не требуют QA. Авто-порог задаётся для профиля через `HH_MATCHER_AUTO_APPLY_MIN_SCORE`; middle-порог остаётся только у QA.

Проверенные неизменённые настройки и данные:

- `config.py:62`, `config.py:239`, `config.py:289`: исходные запросы hh/SuperJob и пути Habr остаются QA-ориентированными; направление должно переопределить их либо выключить источник, как в примере.
- `matcher.py:1053`: резервное письмо читается из `cover_letter_fallback.md` активного профиля; встроенного QA-письма нет. Если такой файл задан, его содержание тоже должно соответствовать направлению.
- `matcher.py:1154`: QA-ориентированные признаки письма вычисляются только для аналитики, не влияют на оценку или текст; телеметрия сохранена.
- `prompt_blocks.py:147`: канонический профиль читается из данных, а не встроенной QA-биографии. В общем knowledge его содержание тоже общее.
- `client_hh_auth.py:146`: фильтр названий резюме по QA включается только для имён `qa/test/tester/manual_qa`; `electrician` проходит без него. Выбор/доставка резюме не менялись.
- `chat_screening.py:53`: среди диагностических слов распознавания скрининга есть API/тестирование наряду с опытом, графиком и образованием; это не фильтр профессии и не источник ответов. Маршрутизация сообщений не менялась.
- `kb_retrieval.py:36`: QA-термины в словаре синонимов являются данными поиска и не требуют QA-навыков у кандидата.

## Проверки

Все входы и ответы моделей синтетические, сетевые соединения запрещены тестовой фикстурой. `tests/test_matcher_directions.py` проверяет нейтральную оценку, границы кандидата, письмо электромонтажника, подтверждённый многолетний стаж, анкеты и пороги. `tests/fixtures/dir1_qa_prompt_sha256.json` хранит SHA-256 полных QA-промптов оценки/письма и блоков style/positioning, снятые до изменений с `2720977` на восьми сценариях. Проверка требует точного совпадения UTF-8 байтов.

```bash
venv/bin/python -m pytest -q tests/ -k "matcher or cover or filter or profile"
venv/bin/python -m pytest -q tests/test_agent_fresh_search.py tests/test_hh_forms.py tests/test_hh_client.py tests/test_google_forms_answering.py tests/test_relevance_verifier.py tests/test_vacancy_prompt_context.py tests/test_kb_retrieval_integration.py tests/test_answer_grounding_regressions.py tests/test_candidate_context.py tests/test_kb_retrieval.py
venv/bin/python -m pytest -q tests/test_emergency_ollama.py tests/test_llm_roles.py tests/test_matcher_deferred_safety.py tests/test_vacancy_prompt_context.py tests/test_run_summary.py
```

Полный сьют не нужен для этого изменения. Отправка, подтверждение доставки, claim/idempotency и телеметрия не изменены.

- Дополнительные затронутые пути анкет/HH: **167 passed**, 16 исходных падений `tests/test_hh_client.py`. На чистом `2720977` этот файл даёт те же **16 failed / 21 passed**.
